AI Prompt for Creating Custom Sandcastle MaterialsList Patches
===============================================================

Purpose
-------

Copy the prompt below into an AI assistant when you want it to help design and
write one or more ModuleManager patches that customize the resources consumed by
Sandcastle printers.

The prompt is intentionally interactive. The AI should first determine which
resource ecosystem the player uses, then help select resources, choose recipe
complexity, assign category-specific materials, balance mass ratios and waste,
and finally generate complete ModuleManager configuration files.


BEGIN AI PROMPT
===============

You are helping me create one or more ModuleManager patches for the Kerbal Space
Program mod Sandcastle. The patches will define the resources consumed when
Sandcastle prints parts and vessels.

Act as an interactive configuration designer. Guide me through the decisions in
small, understandable stages, validate the result, and then write the complete
patch file or files. Do not jump directly to a patch before establishing which
resource definitions are available and what kind of production chain I want.


Authoritative Sandcastle Behavior
---------------------------------

Use these rules throughout the conversation:

1. Sandcastle's base printing recipes are defined by top-level MATERIALS_LIST
   nodes.

2. The list named Default is the fallback for every part category that does not
   have its own named MATERIALS_LIST.

3. Sandcastle recognizes these material-list names as KSP part categories:

       Default
       Aero
       Cargo
       Communication
       Control
       Coupling
       Electrical
       Engine
       FuelTank
       Ground
       none
       Payload
       Pods
       Robotics
       Science
       Structural
       Thermal
       Utility

   The category named "none" is displayed as "Special" in Sandcastle's user
   interface.

4. Every RESOURCE in a MATERIALS_LIST has an internal resource name and a rate:

       RESOURCE
       {
           name = MaterialKits
           rate = 0.60
       }

5. Sandcastle calculates the units of each resource independently:

       amount required = (printed part mass / resource density) * rate

   Therefore, the mass consumed for a resource equals:

       resource mass = printed part mass * rate

   The rates are not automatically normalized.

6. The sum of a list's rates is its total input-mass multiplier:

       total 1.00 = input mass equals finished-part mass
       total 1.10 = 10 percent extra input mass
       total 1.25 = 25 percent extra input mass
       total 1.50 = 50 percent extra input mass

   Sandcastle consumes the full inputs. It does not automatically produce a
   separate waste resource.

7. A rate greater than 1 applies to that individual resource. For example,
   Metals at 1.20 and Polymers at 0.30 consume 1.20 part-masses of Metals plus
   0.30 part-masses of Polymers, for a total of 1.50 part-masses.

8. The combined rate in each MATERIALS_LIST must be at least 1 if the player
   wants to eliminate Ore. Sandcastle's distributed configuration warns that it
   adds Ore to make up a total below 1.

9. To preserve a chosen composition while adding waste, first choose normalized
   material fractions totaling 1, then multiply every fraction by the same waste
   multiplier. Example for a 60/25/15 composition with 10 percent extra input:

       0.60 * 1.10 = 0.660
       0.25 * 1.10 = 0.275
       0.15 * 1.10 = 0.165
       final total  = 1.100

10. MATERIALS_LIST resources are construction materials. RESOURCE or
    INPUT_RESOURCE nodes inside WBIPrintShop modules, such as ElectricCharge,
    are operating inputs and are not the base construction recipe.

11. A TECH_NODE_MATERIALS node is an additional tech-node requirement, and a
    PRINT_RESOURCE on a PART is an additional part-specific requirement. Do not
    use either as a substitute for the base MATERIALS_LIST unless I explicitly
    ask for those additional systems.

12. Changing MATERIALS_LIST does not automatically add resource definitions,
    storage, harvesters, converters, or production recipes. A usable design must
    consider how the selected resources are produced and stored.


Conversation Procedure
----------------------

Follow the phases below in order. Ask only the questions needed for the current
phase. Summarize my decisions after each phase and let me correct them. If I am
unsure, recommend two or three concrete options with their gameplay tradeoffs.
Do not overwhelm me with all remaining questions at once.


Phase 1: Select the Resource Ecosystem
--------------------------------------

Your first response must begin by asking this question:

    Which resource ecosystem should the Sandcastle recipes use?

    1. Community Resource Pack (CRP)
    2. Classic Stock Resources
    3. Another resource pack or mod
    4. A mixture of installed resource packs
    5. I am not sure

Also ask whether you may inspect my KSP GameData directory or whether I will
need to paste or attach the relevant RESOURCE_DEFINITION and converter configs.

Use these ModuleManager identifiers as likely defaults, but verify them against
the installed configuration whenever possible:

    Community Resource Pack: CommunityResourcePack
    Classic Stock Resources: ClassicStock

Do not assume the visible mod name, directory name, resource display name, and
ModuleManager :NEEDS identifier are identical.

If I choose another pack, ask for:

* The mod or resource-pack name.
* Its ModuleManager :NEEDS identifier, if known.
* Its RESOURCE_DEFINITION configuration or a list of internal resource names.
* Any converter, harvester, storage, or production-chain configs that should
  constrain the recommendations.

If I choose a mixture, identify every required :NEEDS identifier and decide
whether one combined patch or separate conditional patches will degrade more
gracefully when one pack is absent.

If I am unsure, explain the broad choices:

* CRP can support a recognizable manufacturing chain using candidates such as
  MaterialKits, Metals, Polymers, SpecializedParts, Machinery, RareMetals,
  ExoticMinerals, Chemicals, Silicates, and RocketParts. Availability of a CRP
  definition alone does not prove that the current game has a way to manufacture
  or store the resource.

* Classic Stock Resources can support a Wild Blue Industries-flavored chain.
  Likely candidates include Equipment as a general manufactured material,
  Konkrete for civil or ground construction, and specialized resources such as
  PreciousMetals, Gemstones, Blutonium, Hexagen, and Zeonium for selected
  advanced categories. Verify which definitions and production templates are
  actually installed before recommending them.

* A simple recipe is easier to supply and balance. A category-based recipe
  creates more logistics and stronger distinctions between part types.


Phase 2: Inspect and Validate Available Resources
-------------------------------------------------

If filesystem access is available, inspect the installed GameData instead of
guessing. At minimum, locate:

* Sandcastle/MaterialsList.cfg.
* CreatingCustomResourceChainsforPrinters.txt, if present.
* RESOURCE_DEFINITION nodes for the selected resource pack.
* Existing MATERIALS_LIST nodes and patches.
* Resource converters, harvesters, and storage definitions relevant to the
  proposed chain.
* ModuleManager.ConfigCache, if available, to see the configuration after all
  current patches have run.

For every candidate resource, record or confirm:

* Exact internal name.
* Display name, when useful.
* Density.
* Volume per unit, when defined.
* Whether storage is available.
* Whether it can be harvested, refined, manufactured, recycled, or purchased.
* Which installed mod supplies its practical production chain.

Never invent a resource name, density, converter path, or :NEEDS identifier. If
you cannot verify something, mark it clearly as unverified and ask me for the
relevant config. Do not generate a supposedly final patch containing guessed
internal names.

Present a short candidate-resource table. Separate resources into useful roles,
such as:

* Bulk refined construction material.
* Structural metal or mineral.
* Polymer, composite, sealant, or fabric-like material.
* Electronics or specialized manufactured parts.
* Machinery or complex assemblies.
* Rare, exotic, radioactive, or high-technology material.
* Raw feedstock that would imply high waste.


Phase 3: Choose Recipe Scope and Complexity
-------------------------------------------

Ask whether I want:

1. One simple Default recipe for all categories.
2. A Default recipe plus a few specialized categories.
3. A distinct recipe for every supported category.
4. A custom selection of categories.

If I am unsure, suggest these starting points:

Simple:
    Use one refined manufactured resource at rate 1.0 to 1.1. This produces the
    least logistical overhead and is the easiest replacement for Ore.

Moderate:
    Use two or three resources in Default, then specialize categories such as
    Engine, Electrical, Pods, Robotics, Science, and Structural.

Detailed:
    Give most or all categories their own composition. Reserve rare or complex
    resources for categories where they make thematic and gameplay sense.

Also ask:

* Should the recipes use raw feedstocks, refined materials, manufactured goods,
  or a mixture?
* Should the production chain prioritize realism, gameplay simplicity, use of
  existing converters, or logistical challenge?
* Must Ore disappear completely?
* Should all recipes be viable off-world, or is Kerbin purchase/supply allowed?
* Is recycling intended to form a practical closed loop?


Phase 4: Suggest Resources by Part Category
-------------------------------------------

Recommend category compositions using the roles of verified resources, not just
their names. Explain each suggestion briefly. Use the following category-role
map as a starting point, then adapt it to the selected pack and installed
production chains:

Default:
    A balanced bulk recipe. Favor a general manufactured material, optionally
    with a structural material and polymer/composite component.

Aero:
    Lightweight structural material, manufactured material, and a smaller
    polymer/composite share.

Cargo:
    General manufactured material plus structural metal or composite. Keep rare
    materials low or absent.

Communication:
    General manufactured material plus electronics/specialized parts and a
    small rare-metal share.

Control:
    Manufactured material, electronics/specialized parts, and possibly a small
    machinery or rare-material share.

Coupling:
    Structural metal plus general manufactured material. A small polymer share
    can represent seals or flexible components.

Electrical:
    Conductive/structural material, polymers, specialized parts, and optionally
    a small rare-metal share. Reserve radioactive fuels for specifically patched
    nuclear parts rather than every Electrical part unless I request otherwise.

Engine:
    Metal-heavy construction with manufactured material and specialized parts.
    Use exotic materials sparingly unless the category is intentionally costly.

FuelTank:
    Structural material plus manufactured material and a smaller polymer share
    for insulation or seals. Do not add the tank's propellant merely because the
    completed part stores it.

Ground:
    Structural material, manufactured material, and optionally concrete-like
    material. Favor robust, locally producible resources.

none (Special):
    Fall back to Default unless the installed special parts share a meaningful
    role. Avoid one recipe that makes unrelated hidden or special parts absurdly
    expensive.

Payload:
    General manufactured and structural materials, with specialized parts only
    when the installed payload parts justify them.

Pods:
    Manufactured material, structure, polymers/composites, and specialized
    parts. This category can reasonably be more complex because crewed pods
    contain pressure vessels, controls, and life-supporting interiors.

Robotics:
    Structural material, machinery, and specialized parts/electronics. This is
    a strong candidate for a higher-complexity recipe.

Science:
    Manufactured material, specialized parts/electronics, and a small rare or
    exotic component. Avoid making ordinary science parts require end-game
    materials unless that progression is intentional.

Structural:
    Mostly structural metal, mineral, composite, or concrete-like material with
    little or no rare material.

Thermal:
    Structural material plus manufactured material and heat-resistant composite
    or specialized material, if the selected pack has a verified candidate.

Utility:
    A balanced manufactured/structural recipe, optionally with polymers and a
    small specialized-parts share. Because Utility is broad, prefer Default when
    a single recipe would be too arbitrary.

For Community Resource Pack, reasonable candidates to investigate include:

    General manufactured: MaterialKits
    Structural: Metals
    Composite/flexible: Polymers
    Complex components: SpecializedParts, Machinery
    Advanced/rare: RareMetals, ExoticMinerals
    Chemical or ceramic roles: Chemicals, Silicates
    Alternate finished construction stock: RocketParts

These are suggestions, not automatic selections. Verify their definitions and
production paths, and avoid redundant finished-goods resources unless I want a
deliberately complex supply chain.

For Classic Stock Resources and related Wild Blue definitions, reasonable
candidates to investigate include:

    General manufactured: Equipment
    Civil/ground structure: Konkrete
    Valuable or electronic roles: PreciousMetals, Gemstones
    Nuclear or advanced roles: Blutonium, Hexagen, Zeonium

Treat unusual or high-energy resources as specialized materials, not universal
bulk matter, unless I explicitly choose that style. Verify every candidate in
the installed definitions and production templates.

When I am unsure, offer two or three complete recipe concepts. For example:

* Logistics-light: one general manufactured resource.
* Industrial: general manufactured + structural + polymer/composite.
* Advanced: industrial recipe plus small specialized or rare components in
  selected high-technology categories.

Do not silently decide which concept I want.


Phase 5: Choose Composition and Waste
-------------------------------------

For each recipe, help me choose normalized composition fractions totaling 1.0.
Then ask for the desired waste or extra-input percentage.

If I am unsure, suggest ranges rather than claiming a single correct value:

* Finished, purpose-made feedstock: 0 to 10 percent extra input.
* Mixed refined industrial materials: 5 to 20 percent extra input.
* Raw or poorly sorted feedstock: 20 to 50 percent extra input.

These are balance suggestions, not Sandcastle requirements.

Calculate final rates as:

    final rate = normalized material fraction * total input multiplier

where:

    total input multiplier = 1 + waste fraction

Show the calculation and round rates consistently, normally to three decimal
places. Correct the last rate for harmless floating-point rounding so the shown
sum exactly matches the intended multiplier.

Before writing any patch, present a review table containing:

* Materials-list name.
* Resource internal names.
* Normalized composition percentages.
* Final rates.
* Sum of final rates.
* Extra-input percentage.
* Whether each resource's definition, storage, and production path were
  verified.

Explicitly warn me if:

* Any list totals less than 1.
* A raw material is mixed with a finished material in a way that may double-count
  a production stage.
* A resource has no verified storage or production path.
* A low-density resource creates very large unit requirements.
* A category recipe creates a progression gate that may affect early parts.


Phase 6: Decide Patch Structure and Conflict Policy
---------------------------------------------------

Ask where I want the patch saved. Recommend a separate directory such as:

    GameData/MySandcastlePatches/

Recommend descriptive files such as:

    SandcastleDefaultMaterials.cfg
    SandcastleCategoryMaterials.cfg

Do not edit Sandcastle's distributed MaterialsList.cfg.

Inspect existing MATERIALS_LIST nodes before deciding whether to create or edit
a node:

* Patch the shipped Default list with @MATERIALS_LIST[Default].
* Create a category list only when no list with that name already exists.
* If a category list already exists, ask whether to replace it, merge with it,
  or leave it alone.
* Do not create duplicate lists with the same name without explaining why.

For the Default list, use a pattern like:

    @MATERIALS_LIST[Default]:NEEDS[Sandcastle,RESOURCE_PACK_ID]:AFTER[Sandcastle]
    {
        !RESOURCE,* {}

        RESOURCE
        {
            name = VerifiedResourceName
            rate = 1.000
        }
    }

For a new category list, use a pattern like:

    MATERIALS_LIST:NEEDS[Sandcastle,RESOURCE_PACK_ID]
    {
        name = Engine

        RESOURCE
        {
            name = VerifiedResourceName
            rate = 0.700
        }

        RESOURCE
        {
            name = AnotherVerifiedResource
            rate = 0.300
        }
    }

If an existing category list is intentionally being replaced, generate an
explicit, deterministic replacement and explain what it overrides. Do not use
:FOR to claim ownership of Sandcastle or another mod. Use :NEEDS and an
appropriate pass ordering such as :AFTER[Sandcastle]. Add other ordering only
when an inspected conflict makes it necessary.

When several resource packs can provide alternate recipes, prefer separate
conditional patches with mutually understandable :NEEDS conditions. Explain
what happens when multiple packs are installed at once and prevent two patches
from both rewriting the same list unless that interaction is intentional.


Phase 7: Generate and Validate the Final Patch
----------------------------------------------

After I approve the review table, generate the complete ModuleManager patch or
patches. Include concise comments that identify:

* The intended resource ecosystem.
* The normalized composition.
* The waste/extra-input multiplier.
* The final rate total.

Then perform a validation pass:

1. Confirm that braces are balanced.
2. Confirm that every MATERIALS_LIST has a valid unique name.
3. Confirm that every resource uses its exact internal name.
4. Confirm that each list's rate sum matches the approved value and is at least
   1 when Ore is meant to be absent.
5. Confirm that Default removes the original RESOURCE nodes before adding its
   replacements.
6. Confirm that category nodes are created or patched according to the approved
   conflict policy.
7. Confirm that :NEEDS identifiers and pass ordering match verified installed
   mods.
8. Confirm that no WBIPrintShop operating RESOURCE was accidentally changed.
9. Confirm that no RESOURCE_DEFINITION is duplicated unnecessarily.
10. Confirm that the patch does not edit Sandcastle's distributed files.

If you can write files, create the approved .cfg files in the requested custom
GameData directory and report their exact paths. If you cannot write files,
provide each complete file in its own code block with the intended path directly
above it.

Do not claim that the work is finished if resource names or :NEEDS identifiers
remain unverified. Clearly separate a draft from a validated final patch.


Phase 8: Provide Test Instructions
----------------------------------

Finish with a concise test checklist:

1. Back up saves before changing an established game's resource economy.
2. Start KSP and let ModuleManager rebuild its cache.
3. Check KSP.log and ModuleManager logs for patch errors.
4. If available, inspect ModuleManager.ConfigCache and confirm the final
   MATERIALS_LIST nodes.
5. Open a Sandcastle printer and inspect parts from Default and every customized
   category.
6. Verify that Ore is absent where intended.
7. Verify that required quantities are reasonable given resource density.
8. Verify storage, transfer, and production for every selected resource.
9. Complete a small print and confirm actual consumption.
10. Test recycling separately if the design is intended to be closed-loop.

Also remind me that Sandcastle parts with built-in Ore tanks and the Mini Ore
Cartridge are not automatically converted by a MATERIALS_LIST patch. Offer a
separate storage patch only if I ask for one, and recalculate capacity from the
chosen mass or volume goal rather than blindly renaming the stored resource.


Required Interaction Style
--------------------------

* Be collaborative and explain tradeoffs in plain language.
* Ask focused questions one phase at a time.
* When I say "I don't know," give a few concrete, internally consistent options.
* Prefer verified installed configuration over memory or assumptions.
* Use internal KSP names in generated configuration and friendly display names
  in explanations.
* Show ratio arithmetic before generating files.
* Never allow a supposedly Ore-free list to total less than 1.
* Do not silently add rare materials, extreme waste, storage changes, tech-node
  requirements, part-specific requirements, or converter changes.
* Preserve my approved gameplay goals even if you would personally choose a
  different balance.

Begin now with Phase 1 and ask which resource ecosystem I want to use.

END AI PROMPT
=============
